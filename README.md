# Medialog

공개 RSS·Atom 기사에서 이슈를 찾아 인스타그램 카드뉴스 초안을 편집하고, 1080×1350 PNG 3~10장과 캡션을 ZIP으로 내보내는 로컬 웹앱입니다.

## 실행

Python 3.12 이상과 한글 글꼴이 필요합니다.

```bash
cd /workspace/Medialog
python -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 로컬 포트 8000에 접속합니다. 클라우드에서 화면을 열려면 사용하는 플랫폼의 포트 연결 기능이 필요합니다. 이 앱은 로그인 기능이 없는 개인용 MVP이므로 기본 실행 주소는 loopback입니다. 공개 배포 전 인증, HTTPS, 요청 제한, 외부 URL 접근을 제한하는 네트워크 프록시를 추가해야 합니다.

Linux 한글 글꼴은 Noto Sans CJK 또는 Nanum Gothic을 사용합니다. 둘 다 없다면 운영체제 패키지 관리자로 `fonts-noto-cjk`를 설치하거나 `MEDIALOG_FONT`에 사용할 한글 TTF/TTC/OTF 파일 경로를 지정하세요. 한글 글꼴이 없으면 기본 폰트로 한글이 정상 표시되지 않을 수 있습니다.

## 사용 순서

1. **RSS 관리**에서 언론사 이름과 언론사가 제공하는 공개 RSS URL을 등록합니다. 연합뉴스의 `https://www.yna.co.kr/rss/news.xml` 같은 주소를 사용할 수 있습니다. 피드 URL과 접근 정책은 언론사에 따라 바뀔 수 있습니다.
2. **이슈 탐색 → 지금 수집하기**를 누릅니다. 실행 중에는 기본 15분 간격으로 모든 등록 피드를 수집합니다. 실패한 피드는 RSS 관리에 오류를 남기고 다른 피드는 계속 처리합니다.
3. **환경설정**에서 기본 구성·디자인을 먼저 저장하세요. **이슈 열기**를 누르면 해당 설정으로 초안이 준비되며, 기존 초안이 있으면 편집 내용을 유지한 채 다시 엽니다. 별도 구성으로 새 제작물을 만들려면 **새 구성**을 누르세요. 장수는 3~10장, 기본은 6장입니다.
4. 카드별 제목, 문구, 근거 기사, 레이아웃, 이미지, 강조색, 캡션을 편집합니다. **레이아웃 · 참고 자료 설정**에서 참고 링크·이미지·디자인 설명을 수정할 수 있습니다. 빈 본문은 원문을 확인하고 직접 작성하세요. 기사 원문 링크를 옆에 제공합니다.
5. **변경 저장**으로 미리보기를 갱신합니다. 모든 카드의 문구와 출처를 확인한 뒤 **검토 완료**에 체크하고 저장합니다.
6. **ZIP 다운로드**로 지정한 장수의 PNG, `caption.txt`, `sources.json`, `design.json`을 받습니다. 검토 전 ZIP 내보내기는 차단하며, 개별 PNG 미리보기에는 초안 표시를 넣습니다.

## 구현 범위

- FastAPI API, SQLite 영구 저장, 별도 빌드가 필요 없는 HTML/CSS/JavaScript UI
- RSS 2.0·Atom 파싱, HTML 태그 제거, XML 외부 엔티티 차단
- URL 정규화와 추적 파라미터 제거를 통한 중복 방지
- 제목 키워드 유사도 기반 이슈 묶기와 최근성·언론사 수 기반 점수
- RSS 요약 문장을 그대로 발췌하는 초안 제작: **AI 요약이나 새로운 사실 생성은 하지 않습니다.**
- 텍스트 중심·밝은 에디토리얼·이미지+텍스트의 세 가지 레이아웃, 장별 레이아웃 재지정
- 장별 역할·제목·순서를 지정하는 초기 구성 설정
- 참고 링크·메모와 PNG/JPEG/WebP 첨부, 썸네일 확인과 카드 이미지 선택
- Pillow 기반 한글 이미지 렌더링, 장별 출처 표기, 검토 상태, ZIP 출력
- 한 피드의 실패가 나머지 수집을 중단하지 않는 비동기 수집

제목 기반 이슈 묶기는 간단한 휴리스틱이라 동일 이슈를 놓치거나 다른 이슈를 묶을 수 있습니다. 원문 링크를 확인하세요. RSS에 정보가 없으면 초안은 빈칸을 남깁니다. 원문 크롤링, 기사 사진 자동 수집, AI 원고 작성, 자동 Instagram 게시, 사용자 인증은 이 버전에 포함하지 않았습니다. RSS의 제목·요약 이용 조건과 저작권은 각 언론사의 정책을 확인하세요.

## 데이터와 환경 변수

데이터베이스는 기본 `data/medialog.sqlite3`에 저장합니다. 첨부 이미지는 해당 DB와 같은 디렉터리의 `uploads/`에 저장하므로 DB와 함께 보관하세요. 삭제하지 않는 한 재시작 후에도 피드·기사·프로젝트가 남습니다. 피드 삭제는 수집된 기사와 제작물을 지우지 않습니다.

| 변수 | 기본값 | 용도 |
|---|---|---|
| `MEDIALOG_DB` | `data/medialog.sqlite3` | SQLite 파일 경로 |
| `MEDIALOG_FONT` | 설치된 Noto/Nanum 글꼴 자동 선택 | 이미지에 사용할 글꼴 |
| `MEDIALOG_POLL_SECONDS` | `900` | 수집 주기, 최소 60초 |
| `MEDIALOG_SCHEDULER` | `1` | `0`이면 정기 수집 중지, 수동 수집은 가능 |

스케줄러 중복 실행을 피하도록 Uvicorn **단일 worker**로 실행하세요. 개발할 때는 `--reload`를 추가할 수 있습니다. 인터넷이 제한된 환경에서는 등록한 RSS 호스트와 리디렉션 대상 호스트의 HTTPS 접근을 허용해야 합니다. API 키나 GitHub 토큰은 필요하지 않습니다.

## 검증

```bash
.venv/bin/python -m pytest -q
node --check app/static/app.js
```

테스트는 독립된 임시 데이터베이스와 RSS·Atom 샘플을 사용합니다. 수집·중복 제거·검색·초안 생성·편집·검토 차단·한글 PNG·ZIP을 실제 API로 실행합니다. 이 테스트 통과는 개별 언론사의 RSS 네트워크 접근을 보장하지 않습니다.

전체 의존성 버전은 `requirements.lock.txt`, 직접 사용하는 의존성은 `requirements.txt`에 기록합니다.

관리형 HTTPS 프록시가 로컬 DNS를 차단하는 환경에서는 프록시의 원격 DNS를 사용합니다. 내부 IP와 로컬 호스트는 거부하지만, 공개 서비스 배포에는 DNS 재바인딩까지 방어하는 별도의 egress 정책이 필요합니다.

API 문서는 서버의 `/docs`, 상태 확인은 `/api/health`입니다. 주요 API는 `/api/feeds`, `/api/collect`, `/api/issues`, `/api/projects`입니다.

## RSS 없이 미리 체험하기

가상 뉴스임을 표시한 데모를 별도 `data/demo.sqlite3`에 준비합니다. 기본 운영 DB는 변경하지 않습니다.

```bash
cd /workspace/Medialog
.venv/bin/python -m app.demo
MEDIALOG_DB=data/demo.sqlite3 MEDIALOG_SCHEDULER=0 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

포트 8001에서 이슈 탐색이나 제작 보관함을 열고 편집·저장·검토 완료·ZIP 다운로드를 체험할 수 있습니다. 데모 원문 주소는 예시용으로, 실제 기사 링크가 아닙니다. 이 모드는 외부 RSS 연결이나 자동 수집을 검증하지 않습니다.

## 초기 레이아웃과 참고 자료

**환경설정**에서 기본값을 저장하거나 이슈의 **새 구성**에서 다음을 설정할 수 있습니다.

- **장수·구성:** 3~10장, 표지/핵심 사실/배경/영향·전망/출처/직접 작성 역할과 장별 제목, 위·아래 버튼으로 순서 변경
- **디자인:** 텍스트 중심, 에디토리얼, 이미지+텍스트 중 선택; 강조색과 디자인 방향 메모
- **레퍼런스:** HTTP(S) 링크와 참고할 요소 설명 최대 10개, PNG·JPEG·WebP 이미지 최대 10개

이미지는 파일당 8MB, 2천만 화소 이하를 지원합니다. 실제 파일 형식을 검사하고 EXIF 방향을 적용한 뒤 메타데이터 없이 PNG로 저장하며 (투명 이미지의 알파 채널 유지), 긴 변을 최대 2400px로 축소합니다. 원본 파일을 보존하는 기능은 아닙니다. 이미지+텍스트 레이아웃은 이미지를 가로 영역에 맞춰 중앙 크롭합니다. 카드별 이미지 선택에서 사진을 바꿀 수 있고, 전체 레이아웃 대신 장별 레이아웃을 지정할 수도 있습니다.

참고 링크나 이미지, 디자인 메모는 프로젝트에 보관하는 브리프입니다. 링크의 내용을 다운로드하거나 AI가 이미지를 분석해 스타일을 복제하지 않습니다. 메모는 렌더링 설정을 자동으로 바꾸지 않으며, 선택한 레이아웃·강조색·카드 이미지만 출력에 반영합니다. 직접 작성 역할은 빈 문구로 시작합니다. 배경·영향 역할에 자동 배치된 RSS 문장의 적합성은 원문으로 검토하세요.

기존 6장 프로젝트도 열어서 새 디자인 설정을 사용할 수 있습니다. 참고 이미지 첨부 해제는 프로젝트에서 연결을 제거하며, 서버에 보관한 이미지 파일은 자동 삭제하지 않습니다.

## PC 데모 배포

Windows에서는 `start-windows.bat`, macOS에서는 `start-macos.command`를 사용하세요. 또는 Python 3.12를 설치한 뒤 `python start_demo.py`로 실행하세요. 시작기는 `.venv-pc`에 의존성을 설치하고 별도 데모 DB를 준비한 다음 준비 상태를 확인하고 브라우저를 엽니다. 자세한 설치·종료 방법은 [PC-DEMO.md](PC-DEMO.md)를 참고하세요. 배포 ZIP에는 한글 글꼴과 해당 라이선스도 포함됩니다.

## 환경설정과 자산 보관함

**환경설정**에서 기본 장수·장별 역할·순서·제목, 레이아웃·강조색·공통 로고·참고 링크·이미지를 저장합니다. 설정은 SQLite에 저장되며 다음 실행에서도 유지됩니다. 새 이슈를 열거나 **새 구성**을 시작할 때 불러오고 기존 제작물은 바꾸지 않습니다.

**자산 보관함**에 로고나 반복 사용하는 이미지를 업로드하면 다른 프로젝트에서도 재사용할 수 있습니다. 기본 설정의 공통 로고는 모든 카드 상단에 표시하며, 투명 PNG를 지원합니다. 참고 이미지 영역의 **보관함에서 선택**으로 카드에 사용할 이미지를 고르세요. 프로젝트나 기본 설정에서 사용 중인 자산은 삭제를 차단합니다.

**이슈 열기**는 별도 구성 창 없이 초안을 준비하고 편집 화면을 엽니다. 같은 이슈의 초안이 있으면 다시 생성하지 않고 편집한 문구와 디자인을 유지합니다. RSS가 갱신되어 관련 기사가 늘어도 기존 초안은 자동 덮어쓰지 않습니다. 다른 구성으로 제작하려면 **새 구성**을 사용하세요.

이슈 요약은 관련 기사들의 RSS 문장에서 중복 문장과 저작권 안내를 제거하고 여러 출처를 번갈아 반영하는 발췌 방식입니다. AI 요약이나 원문 자동 수집이 아니므로 RSS에 본문 정보가 부족하면 원문 확인 필요를 표시하며 부족한 내용을 만들지 않습니다.

이미지 첨부 결과와 초안 생성 오류는 구성 설정 창 내부에 표시합니다. 빈 참고 링크 행은 무시하지만 설명만 입력한 행에는 URL이 필요합니다. `example.com/reference`처럼 프로토콜이 없는 참고 링크에는 HTTPS를 붙입니다. 업로드 중에는 초안 생성 버튼을 잠시 비활성화합니다.

업데이트할 때는 실행 중인 터미널에서 Ctrl+C로 종료하고 최신 코드를 받으세요. 기존 `data/` 폴더를 보관하거나 새 폴더로 옮기면 피드·작업물·환경설정·자산을 유지할 수 있습니다. `.venv-pc/`는 새 폴더로 옮기지 않아도 시작기가 다시 준비합니다.
